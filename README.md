# LSS to Foundry — расширение Chrome

Неофициальное расширение: использует текущую сессию Long Story Short, показывает персонажей и передаёт выбранного персонажа в модуль `lss-to-foundry` в открытом мире Foundry.

Статус: первая реализация. Автоматические тесты проходят; реальные запросы из установленного расширения и импорт в Foundry ещё требуют проверки. Открытая вкладка пользователя подтвердила авторизацию и наличие 24 персонажей, но это не подтверждает ответ API расширению.

## Установка для проверки

1. Откройте `chrome://extensions` в Chrome.
2. Включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите папку `F:\LongStoryShort\lss-to-foundry-extension`.
3. Откройте расширение. При действующей сессии LSS оно загрузит список персонажей. Иначе нажмите «Войти в LSS», войдите на официальном сайте и снова откройте расширение. Обычный popup Chrome закрывается при переходе во вкладку входа; пароль в расширение не вводится.
4. Откройте мир Foundry в этом же профиле Chrome и включите `LSS to Foundry`. В расширении раскройте «Подключение к Foundry», введите её адрес, нажмите «Подключить» и разрешите доступ к этому адресу.
5. Выберите вкладку мира и нажмите «Импорт» у нужного персонажа. Модуль использует свои текущие настройки. Требуются система dnd5e и право `ACTOR_CREATE`.

После изменения исходников нажмите «Обновить» у расширения на странице `chrome://extensions`. Сборка и установка зависимостей для работы не нужны.

## Вход и полный выход

Сайт LSS хранит JWT в куке `lss-jwt`. Фоновая часть читает её через `chrome.cookies`, а затем проверяет сессию запросом `GET https://api.longstoryshort.app/character/list/`. Наличие куки само по себе не считается успешной авторизацией. При 401 показывается вход; ошибки сети, прав и лимита запросов показываются отдельно.

Кнопка «Выйти» с подтверждением удаляет доступные куки `lss-jwt` для LSS, очищает резервный `lss-iframe-token` в открытых LSS-вкладках и обновляет их. Это полный локальный выход для данного профиля, а не только отключение расширения. Кука может быть общей с другими продуктами LSS. Уже выданный JWT на сервере не отзывается: серверный контракт отзыва не найден. Другие устройства и профили не затрагиваются. Если часть вкладок не удалось очистить, расширение просит закрыть или обновить их; встроенные LSS-фреймы в других приложениях также следует закрыть или обновить.

## Передача в Foundry

Расширение обращается к API только на чтение. Полный персонаж загружается по выбранному id через `/character/:id/`, а в Foundry передаётся конверт `jsonType`, `version`, `edition`, `sheetEdition`, `spells`, `disabledBlocks`, `data`. Модуль получает его через существующий публичный API `parseLssFile` / `importCharacters`.

Предварительно проверяются вкладка, точный origin с портом, включённый модуль, система и права. Контекст страницы проверяется повторно перед записью. Отдельный мост и обновление кода модуля не нужны. Страница Foundry и установленные в ней модули видят импортируемые данные, как и при обычном импорте файла.

Каждый импорт создаёт нового актёра. Повторное нажатие после завершения создаст дубликат. Пока операция идёт, второй импорт отклоняется. Состояние последней операции хранится в `storage.session`, поэтому закрытие popup не скрывает результат; после прерывания фонового процесса расширение просит проверить мир, а не повторяет запись автоматически.

Свои заклинания из Гримуара пока передаются отдельным JSON через обычный импорт модуля. Расширение не обещает полноценный перенос Гримуара по одному документу персонажа. Предупреждения существующего импортёра, включая неподдержанные старые бонусы LSS, этим расширением не исправляются.

## Разрешения и данные

- `cookies` + доступ к `longstoryshort.app`: текущая авторизация, полный выход.
- Доступ к `api.longstoryshort.app`: чтение списка и выбранного персонажа.
- `storage`: адрес Foundry; временное состояние последнего импорта. Персонажи и JWT не сохраняются расширением на диск.
- `scripting`: вызов публичного API модуля в выбранной вкладке; очистка резервного токена при полном выходе.
- Дополнительный доступ к Foundry выдаётся по нажатию «Подключить». В Chrome разрешение охватывает все порты хоста; расширение дополнительно проверяет сохранённый точный origin.

Нет постоянных content scripts, аналитики, стороннего сервера, удалённо загружаемого кода или внешних сообщений от веб-страниц. Токен остаётся в фоновой части, не попадает в popup, Foundry или сообщения об ошибках. Не добавляйте реальные экспорты, значения cookies и ключи в Git.

## Браузеры

Цель первой версии — Chrome 120+. Для Opera ожидается возможность использовать тот же Manifest V3 благодаря Chromium, но работа в Opera не проверена. Firefox использует WebExtensions, однако для фоновой части потребуется отдельный вариант манифеста и проверка API, cookies и выдачи разрешений. Поддержка Firefox пока не заявлена.

## Проверки

`npm test` запускает тесты через встроенный Node.js test runner; зависимости не требуются. `npm run check` проверяет синтаксис точек входа. Node.js 22+.

Перед выпуском проверить:

- Действующую сессию: список расширения совпадает со списком LSS. Истёкшая/отсутствующая сессия показывает вход; после входа список появляется при открытии popup.
- Полный выход с одноразовым тестовым аккаунтом: LSS-вкладки теряют доступ после обновления; другие данные сайта не удаляются. Не проверять выход во время несохранённых правок листа.
- Сеть отключена, 401, 403, 429 и неожиданная форма API отображаются как разные состояния.
- Подключение `localhost:30000` не позволяет импортировать во вкладку `localhost:30001`.
- В отдельном тестовом мире: персонажи 2014/2024 импортируются с ожидаемыми числами, модуль без прав и чужая система отклоняются до загрузки полного документа.
- Закрытие popup во время импорта не вызывает повторный импорт; состояние восстанавливается. После потери связи проверка мира обязательна.
- На существующие пользовательские миры тесты не направлять без явного выбора пользователя.

## Источники и ограничения API

Используются внутренние маршруты текущего клиентского приложения LSS. Пользователь 22.10.2026 разрешил проверку своей текущей сессии и предложил эту схему доступа; это уточнение заменяет прежний запрет на такие проверки для данного задания. Стабильный публичный контракт стороннего API или разрешение LSS на публикацию такого клиента этим не подтверждены. При изменении формы API расширение завершает операцию с ошибкой и не пытается угадывать поля.
